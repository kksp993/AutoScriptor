# 视觉定位经验

对密集游戏 UI 做 grounding 时，优先缩小候选区域。

- 小图标或小文字在全屏截图中容易被模型定位到 `(0,0)` 附近，必须用 ROI 裁剪后再找。
- ROI 结果要换算回全屏坐标：`abs_x = roi_left + crop_x`，`abs_y = roi_top + crop_y`。
- 点击后必须截图验证页面确实变化；没有变化时，不要继续沿错误状态推理。
- 对短暂 toast，提交后要连续抓取多帧，否则可能错过返回结果。
- toast 很短时，先用 0.1-0.2 秒间隔快速缓存帧，再离线 OCR；边 OCR 边等下一帧容易错过提示窗口。
- 输入文本后，如果系统输入层遮挡游戏按钮，先发送 Enter 或收起输入层，再点击游戏按钮。
- 游戏活动页的艺术字标签常被 OCR 合并成一整行文本；脚本可以用 ROI OCR 的 substring 判断做状态确认，再使用已验证坐标点击。

生成正式 AutoScriptor 任务脚本时，这些经验要压缩成简单动作：

- 能用 `T("文字", box=Box(...).margin())` 就不要生成底层截图/OCR 代码。
- 能用已验证坐标 `B(...)` 点击就直接点，不要把 grounding 分析过程写进脚本。
- 视觉模型 grounding 只服务于生成阶段；最终脚本不能包含 `V(...)`，要转成 `T(...)`、`I(...)`、`B(...)` 或 `extract_info(B(...))`。
- 连续截图、离线 OCR、VLM grounding 只写进调试探针或经验总结，不默认写进 `data/custom_task` 正式脚本。
