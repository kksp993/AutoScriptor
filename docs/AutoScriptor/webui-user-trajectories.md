# WebUI User Trajectories

这些轨迹是后续回归测试和手工验收的基础。它们覆盖的是 WebUI/生命周期，不覆盖具体游戏业务脚本是否能打完。

## 任务编辑保存

1. 打开每日/每周任务。
2. 进入一个关闭任务的编辑弹窗。
3. 打开开关并保存。
4. 弹窗关闭，任务仍为启用。
5. 刷新页面后状态仍为启用，且 `next_exec_time=0` 时显示为待执行。

## 调度队列

1. 在总览页添加多个角色到调度队列。
2. 调整顺序并刷新页面。
3. 顺序保持不变。
4. 点击开始调度后只执行队列内角色，且按队列顺序执行。

## 停止执行

1. 开始调度或直接执行任务。
2. 在启动模拟器、等待登录、脚本 sleep 或重试等待阶段点击停止。
3. WebUI 快速进入停止中，然后回到待运行。
4. 后续任务链不再继续执行。

## 设备诊断

1. 打开“启动诊断”页。
2. 默认刷新只检查 Manager、ADB、App、OCR、UI Map，不触发截图。
3. 点击“截图探测”后才检查 NemuIpc。
4. 当 MuMuManager 失败但 ADB 正常时，Manager 显示注意，整体按 ADB/App/NemuIpc 结果判断。

## 安装器

1. 首次运行创建 `.venv` 并安装依赖。
2. 自动探测 MuMu 路径并写入 `config.json`。
3. MuMuManager `version` 失败但 ADB 可用时，不阻断安装。
4. `install-only` 目标完成后不启动 WebUI。
