# 后台调度器（Scheduler）使用指南

## 📖 概述

后台调度器是 AutoScriptor 的**自动任务执行系统**，可以在你不在电脑前时自动运行任务。

### 核心功能

- ⏰ **定时检查**：每小时自动检查一次是否有到期任务
- 🚀 **自动执行**：发现到期任务后自动启动模拟器并执行
- 📊 **状态管理**：实时显示调度器状态（待运行/运行中/发生错误）
- 🔄 **智能重试**：连续失败 3 次后自动停止，避免无限重试

---

## 🎯 使用场景

### 典型场景

1. **晚上睡觉前**：设置好任务，第二天早上自动执行
2. **上班期间**：让电脑自动运行任务，下班回来查看结果
3. **长期挂机**：24/7 自动运行，无需人工干预

### 工作流程

```
1. 用户按下【开始执行】→ 调度器状态变为"运行中"（🟡）
2. 调度器每小时检查一次到期任务
3. 发现到期任务 → 自动启动模拟器 → 执行任务
4. 任务完成 → 更新下次执行时间 → 继续等待
5. 如果连续失败 3 次 → 状态变为"发生错误"（🔴）→ 停止自动执行
```

## 📊 状态说明

调度器有三种状态，用颜色和图标标识：

### 🟢 待运行（PENDING）

**含义**：调度器已启动，但尚未激活自动执行

**触发条件**：
- 程序刚启动时
- 用户退出程序时
- 账密未验证时
- 手动恢复错误状态后

**行为**：不会自动执行任务，只等待用户手动执行

### 🟡 运行中（RUNNING）

**含义**：调度器已激活，正在后台监控并自动执行任务

**触发条件**：
- 用户按下【开始执行】按钮（CLI 或 WebUI）

**行为**：
- ✅ 每小时检查一次到期任务
- ✅ 发现到期任务后自动执行
- ✅ 执行完成后更新任务状态

**显示位置**：
- CLI：主菜单的【开始执行】按钮旁显示 `🟡运行中`
- WebUI：控制按钮栏显示调度器状态标签

### 🔴 发生错误（ERROR）

**含义**：调度器因连续失败而停止自动执行

**触发条件**：
- 连续 3 次任务执行失败（有任务失败即算一次失败）

**行为**：
- ❌ 停止自动执行任务
- ⚠️ 需要手动恢复才能继续

**恢复方法**：
- CLI：在主菜单选择【开始执行】（会自动恢复）
- WebUI：点击【恢复调度】按钮

## 🔧 配置说明

### 检查间隔

调度器默认**每小时**检查一次到期任务：

```python
CHECK_INTERVAL = 3600  # 秒（1 小时）
```

**为什么是 1 小时？**
- ✅ 平衡及时性和资源消耗
- ✅ 避免频繁检查导致 CPU 占用
- ✅ 大多数任务都是按天/周执行的，1 小时精度足够

### 失败阈值

连续失败 **3 次**后进入错误状态：

```python
MAX_CONSECUTIVE_ERRORS = 3
```

**计数规则**：
- 一次执行中，只要有任务失败，就算一次失败
- 成功执行会重置失败计数
- 连续 3 次失败后停止自动执行

## 🔍 工作原理

### 极简设计

调度器采用**极简设计**，几乎零开销：

```python
def _loop(self):
    """主循环：用 Event.wait(timeout) 实现可中断的 sleep"""
    while not self._stop.wait(CHECK_INTERVAL):  # 等待 1 小时
        if self.state != SchedulerState.RUNNING:
            continue
        self._check_and_run()  # 检查并执行任务
```

**关键点**：
- ✅ 使用 `Event.wait(timeout)` 实现可中断的 sleep
- ✅ 99.9% 时间在 sleep，几乎不消耗 CPU
- ✅ 无锁、无单例，简单可靠

### 任务收集

调度器会递归扫描所有任务，找出到期任务：

```python
def _collect_due(self, node: dict, prefix: str, now_ts: float) -> list:
    """收集 on=True 且 next_exec_time <= now 的任务"""
    tasks = []
    for key, val in node.items():
        if "fn" in val and "on" in val:  # 叶子任务节点
            if val.get("on") and now_ts >= val.get("next_exec_time", 0):
                tasks.append(path)  # 找到到期任务
        else:
            tasks.extend(self._collect_due(val, path, now_ts))  # 递归目录
    return tasks
```

### 自动执行流程

```
1. 检查到期任务
   ↓
2. 启动模拟器（如果未运行）
   ↓
3. 执行任务（调用 TaskManager.execute_tasks）
   ↓
4. 记录结果（成功/失败）
   ↓
5. 更新调度器状态（如果连续失败 3 次 → ERROR）
   ↓
6. 执行后动作（关闭模拟器/关闭游戏/无操作）
   ↓
7. 继续等待下一个检查周期
```

## ⚙️ 执行后动作

任务执行完成后，可以根据配置执行不同动作：

### 配置位置

`config.json` → `emulator.post_execution`

### 可选值

| 值 | 说明 | 行为 |
|----|------|------|
| `NULL` | 什么都不做（默认） | 保持模拟器和游戏运行 |
| `CLOSE_GAME_ONLY` | 仅关闭游戏 | 关闭游戏应用，模拟器继续运行 |
| `CLOSE_MUMU` | 关闭模拟器 | 关闭游戏 + 关闭模拟器 |

### 配置示例

```json
{
  "emulator": {
    "index": 1,
    "adb_addr": "127.0.0.1:16416",
    "post_execution": "CLOSE_MUMU"  // 执行完任务后关闭模拟器
  }
}
```

### 使用场景

- **`NULL`**：适合需要保持游戏在线的场景
- **`CLOSE_GAME_ONLY`**：适合需要保持模拟器运行，但关闭游戏省电的场景
- **`CLOSE_MUMU`**：适合完全自动化，执行完就关闭的场景

## 📝 任务时间设置

### 任务类型与刷新规则

| 任务类型 | 刷新规则 | 说明 |
|----------|----------|------|
| 每日任务 | 明天 5:00 | 每天早上 5 点后视为第二天 |
| 每周任务 | 下周一 5:00 | 每周一早上 5 点刷新 |
| 活动任务 | 明天 5:00 | 24 小时刷新，同每日任务 |
| 一般任务 | 执行后关闭 | 执行一次后自动关闭（`on=False`） |

### 自定义执行时间

任务可以自定义 `next_exec_offset_hours` 字段，设置"X 小时后执行"：

```json
{
  "tasks": {
    "每日任务": {
      "某个任务": {
        "on": true,
        "next_exec_offset_hours": 6,  // 执行后 6 小时再运行
        "fn": "..."
      }
    }
  }
}
```

**优先级**：
1. 函数参数（`offset_hours`）
2. 任务字段（`next_exec_offset_hours`）
3. 默认类别规则（每日/每周/活动）

## ⚠️ 注意事项

### 1. 账密验证

**重要**：调度器只有在账密已验证的情况下才会自动执行任务。

- ✅ 如果账密未验证，调度器会保持"待运行"状态
- ✅ 手动执行任务时会提示先验证账密
- ✅ 验证账密后，调度器才能正常工作

### 2. 模拟器启动

调度器会自动启动模拟器（如果未运行），但需要：
- ✅ 配置正确的 `emulator.emu_path` 和 `emulator.adb_path`
- ✅ 模拟器安装路径正确
- ✅ ADB 连接正常

### 3. 错误处理

- ✅ 单次任务失败不会停止调度器
- ✅ 连续失败 3 次才会进入错误状态
- ✅ 进入错误状态后需要手动恢复

### 4. 资源消耗

调度器设计为**极低开销**：
- ✅ 99.9% 时间在 sleep，几乎不消耗 CPU
- ✅ 只在检查时才会扫描任务配置
- ✅ 不会影响系统性能

## 🔍 故障排查

### 问题：调度器不自动执行任务

**检查清单**：
1. ✅ 状态是否为"运行中"（🟡）？
2. ✅ 账密是否已验证？
3. ✅ 任务是否已开启（`on=True`）？
4. ✅ 任务的 `next_exec_time` 是否已到期？
5. ✅ 查看日志中是否有调度器检查记录

### 问题：调度器进入错误状态

**可能原因**：
- 连续 3 次任务执行失败
- 模拟器启动失败
- ADB 连接问题

**解决方法**：
1. 检查日志，找出失败原因
2. 修复问题后，手动恢复调度器
3. 重新激活调度器

### 问题：任务执行时间不准确

**检查**：
- 确认任务的 `next_exec_time` 是否正确设置
- 检查系统时间是否正确
- 查看日志中的任务执行时间
