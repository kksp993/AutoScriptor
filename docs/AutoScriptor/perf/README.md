# 性能优化与后台调度文档

本目录包含 AutoScriptor 性能优化和后台调度相关的详细文档。

## 📚 文档索引

### [性能优化模块（perf）](./perf.md)

详细介绍 `perf` 模块的功能和使用方法：

- ✅ **核心功能**：进程优先级提升、阻止系统休眠、线程优化
- ✅ **延迟执行机制**：只在真正使用 API 时才启用，避免不必要的开销
- ✅ **自动恢复机制**：多重保障，确保程序退出时正确恢复
- ✅ **故障排查**：常见问题和解决方法

**适用场景**：
- 需要了解性能优化的工作原理
- 遇到后台运行卡顿问题
- 需要自定义性能优化参数

---

### [后台调度器（Scheduler）](./scheduler.md)

详细介绍后台任务自动执行系统：

- ✅ **状态管理**：待运行（🟢）/ 运行中（🟡）/ 发生错误（🔴）
- ✅ **自动执行**：每小时检查一次到期任务，自动启动并执行
- ✅ **智能重试**：连续失败 3 次后自动停止，避免无限循环
- ✅ **执行后动作**：支持关闭模拟器/关闭游戏/保持运行

**适用场景**：
- 需要设置自动任务执行
- 了解调度器的工作机制
- 排查调度器相关问题

## 🚀 快速开始

### 性能优化

大多数情况下，你**不需要**手动调用 `boost()`，系统会在首次使用 API 时自动启用：

```python
from AutoScriptor import click, T

# 首次调用 click() 时会自动启用性能优化
click(T("开始按钮"))
```

### 后台调度

1. **激活调度器**：在 CLI 或 WebUI 中点击【开始执行】
2. **查看状态**：主菜单或控制栏会显示调度器状态
3. **自动执行**：调度器每小时检查一次，发现到期任务自动执行

## 💡 常见问题

### Q: 为什么验证账号时会触发性能优化？

**A**: 这是旧版本的问题，新版本已修复。现在采用延迟执行机制，只有在真正使用 API（如 `click()`、`locate()`）时才会启用性能优化。

### Q: 调度器为什么不自动执行任务？

**A**: 检查以下几点：
1. 调度器状态是否为"运行中"（🟡）？
2. 账密是否已验证？
3. 任务是否已开启（`on=True`）？
4. 任务的 `next_exec_time` 是否已到期？

### Q: 如何自定义任务执行时间？

**A**: 在任务配置中添加 `next_exec_offset_hours` 字段：

```json
{
  "tasks": {
    "每日任务": {
      "某个任务": {
        "on": true,
        "next_exec_offset_hours": 6,  // 执行后 6 小时再运行
        "fn": "..."
      }
    }
  }
}
```
