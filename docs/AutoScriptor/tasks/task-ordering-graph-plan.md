# Task Ordering Graph Plan（已废弃）

本文件保留为历史路径占位。当前主线不再维护任务计算图、DAG 画布、bind 气泡、强制先后规则或节点布局保存。

## 当前事实

- WebUI 只有一个“任务列表”入口。
- 左侧显示可拖拽的任务总列表；拖到上/下边缘会在同级列表插入排序，拖到任务中部会创建灰色分组，拖到分组中部会加入分组，分组内部也按同样规则支持排序、嵌套、重命名、展开/收起、移除并保持组内顺序。未启用任务的左侧编号使用灰色弱化。
- 右侧显示当前已启用任务的紧凑执行列表，任务名前的小圆点沿用总览页状态颜色；可点选某个任务并点击播放按钮，从该任务开始按右侧顺序执行到末尾。运行态下，当前执行任务会使用同一高亮光圈并显示“当前”；点击右侧任务会把左侧顺序列表导览到对应任务位置。
- 任务顺序模块右上角可切换“仅显示执行任务”，并提供“折叠全部分组”文本操作用于一键收起左侧所有分组。
- 持久化位置仍是 `data/config.json` 的 `task_ordering`。
- `task_ordering` 当前保存可嵌套顺序结构；执行时递归展开分组，`user_order` 是展平兼容投影：

```json
{
  "schema_version": 1,
  "items": [
    {"type": "task", "path": "每日任务/村庄/宠物培养"},
    {
      "type": "group",
      "id": "group-example",
      "name": "日常组合",
      "expanded": true,
      "items": [
        {"type": "task", "path": "每日任务/村庄/领取奖励"},
        {"type": "task", "path": "每日任务/村庄/宠物训练"}
      ]
    }
  ],
  "user_order": ["每日任务/村庄/宠物培养", "每日任务/村庄/领取奖励", "每日任务/村庄/宠物训练"]
}
```

## 兼容边界

- `_order.txt` 仍只是内置源码导入/注册 seed，不是用户排序持久化位置。
- 旧版本遗留的 `hard_edges`、`layout`、`group_order` 输入会被后端规范化忽略。
- `/api/task-ordering/layout` 仅作为旧客户端兼容 no-op 保留；当前前端不再调用。
- 有效执行/显示顺序是确定性总排序：先递归展开 `items`，再回退到当前任务树顺序、运行时注册顺序和路径字典序。单元素分组会被规范化打散，不作为持久结构保留。

## 不再作为目标的内容

- 不再拆分“任务列表”和“任务计算图”两个 TASKS 页面。
- 不再加载 `TaskDagCanvas.js` 或 `TaskRulesPanel.js`。
- 不再维护图节点坐标、鸟瞰图、虚线执行序列、强制规则边、冲突删边弹窗或 bind 取消气泡。
- 不再用稳定拓扑排序解释任务顺序；保存排序也不再做循环图检查。

如果未来重新引入图形化任务规划，需要重新写一份当前需求文档，不能把本文件的旧方案当作主线事实恢复。
