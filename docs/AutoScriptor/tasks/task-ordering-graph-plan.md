# 任务列表与依赖就近调度

当前采用任务级前置约束和动态就近调度。任务页提供分层管理、顺序编排和计算图三个视图；计算图是现有任务配置的投影，不恢复旧 DAG 编辑器、bind 气泡或节点坐标存储。

## 自动调度算法

- 沿用 `is_task_due()`：启用、到期、时间窗口、星期与人工接管冷却语义不变。
- `after_tasks` 使用稳定任务 ID，多项为 AND。只在前置任务当前仍待执行时阻塞；关闭、延期和成功推进时间均解除约束，不要求额外成功凭据。
- 从当前依赖子图入度为 0 的任务里选择，不按固定拓扑层逐层执行。前置重试耗尽仍待执行时，不能因它被过滤而放行后继。
- `@register_task(ensure_in=...)` 必填，声明真实导航起点；普通任务须提供非空注册地点。只有保留现场/外部 App 等 debug 任务可显式声明 `None`，不能省略或用空列表代替。声明本身不导航，实际 `ensure_in(...)` 保留在业务流程正确的位置。
- `preferred_locations` 可多选，仅用于排序；未另行声明时默认取 `ensure_in`。用户可覆盖/清空偏好，但不能改变源码起点。任务自行导航，不会预导航或把推荐地点当成结束地点。
- `task_ordering.selection_policy` 默认 `nearest_ready`，排序键为 `(最短导航步数, 有前序且已就绪优先, 列表序号, 稳定ID)`。距离永远先比较，已就绪后继不能越过更近的独立任务；`list_ready` 只按列表决胜，两者都遵守依赖。
- 成本采用现有有向导航图，每边 1 步，包含退出/进入子地点；多地点取最小值，不代表秒数或全局最优。未知位置、无偏好、不可达按无限距离处理，在同距离内仍先前序就绪再列表决胜，但不会因此禁止执行。
- 每个任务后重新收集。失败任务先让其他首次尝试任务执行，再按尝试次数分轮重试；解锁的后继从自己的第 1 次开始。
- 跨角色保持 `dispatch_queue`。全链阻塞时等待已有时间/配置唤醒，不进行零间隔空转。
- 手动单任务和列表直跑保持原顺序，不受自动调度依赖限制。

任务声明的默认值在注册表，角色覆盖值在 `cfg["tasks"]`；字段缺失为继承，空列表为明确清空。保存任务时检查未知引用、自依赖和环；热重载失效时显示诊断，受影响链停止自动调度，无关任务继续。

## 当前事实

- WebUI 只有一个“任务列表”入口。
- 默认“分层管理”按显示路径构建目录，初始只显示顶层分类与任务/启用/到期/异常汇总；逐级展开或搜索定位，不再把几十项平铺。展开状态仅用于浏览，不改路径、全局顺序或账号数据。
- “顺序编排”保留可拖拽的任务总列表；拖到上/下边缘会在同级列表插入排序，拖到任务中部会创建灰色分组，拖到分组中部会加入分组，分组内部也按同样规则支持排序、嵌套、重命名、展开/收起、移除并保持组内顺序。未启用任务的左侧编号使用灰色弱化。
- 右侧显示当前已启用任务的紧凑执行列表，任务名前的小圆点沿用总览页状态颜色；可点选某个任务并点击播放按钮，从该任务开始按右侧顺序执行到末尾。运行态下，当前执行任务会使用同一高亮光圈并显示“当前”；点击右侧任务会把左侧顺序列表导览到对应任务位置。
- 三视图共用顶部唯一的任务模糊搜索框，匹配任务路径、任务名、状态及对象内的字段/属性/参数；下拉项以 `xxx/xxx/xxx` 路径标识，选中后按当前视图展开目录、顺序分组或计算图牌堆并定位任务。“顺序编排”仍提供“仅显示启用任务”和“折叠全部分组”操作。
- 持久化位置仍是 `data/config.json` 的 `task_ordering`。
- `task_ordering` 当前保存可嵌套顺序结构，**以任务 `id` 为键**（`id` 就是任务名，换目录不变；重命名文件时由 `@register_task(id="旧任务名")` 钉住）；执行时先把 `id` 换成显示路径，再递归展开分组，`user_order` 是展平兼容投影：

```json
{
  "schema_version": 1,
  "selection_policy": "nearest_ready",
  "items": [
    {"type": "task", "id": "宠物培养"},
    {
      "type": "group",
      "id": "group-example",
      "name": "日常组合",
      "expanded": true,
      "items": [
        {"type": "task", "id": "领取奖励"},
        {"type": "task", "id": "宠物训练"}
      ]
    }
  ],
  "user_order": ["宠物培养", "领取奖励", "宠物训练"]
}
```

## 兼容边界

- 内置任务的默认顺序来自源码路径排序，不是用户排序的持久化位置。
- 旧版本遗留的 `hard_edges`、`layout`、`group_order` 输入会被后端规范化忽略。
- `/api/task-ordering/layout` 仅作为旧客户端兼容 no-op 保留；当前前端不再调用。
- 显示/手动执行及自动调度的决胜顺序是确定性总排序：先把存储里的 `id` 键换成显示路径，再递归展开 `items`，最后回退到当前注册顺序和路径字典序。单元素分组会被规范化打散。

## 计算图

- `TaskPlanningGraph.js` 使用纯展示模块 `taskPlanningLayout.js`；不新增侧栏页面。省略虚拟“登录界面”和入口连线，只画任务之间真实依赖。
- 先构建依赖主干：参与任一有效依赖的任务各占一张主干牌，最长前序链深度决定从左到右的列。按子树占用排成思维导图，父子主支对齐；多前序共享同一后继卡片，非主支连线淡显，跨级线通过中间列的卡间空隙，不穿过卡片。仅省略已由中间链路表达的传递冗余边，保存的完整 AND 前序不删改。无效引用/环单独显示可点击诊断。
- 不参与任何依赖的任务按主干起点到自身起点的最小有向距离归堆，优先 0 距离，允许挂到第二层或更深主干。只选择已启用主干；同距先较早层，再原有效列表顺序。堆内主干牌始终在前，附牌按距离/列表顺序排列；附牌不继承主干依赖、不改变真实拓扑或执行优先级。不提供叠牌开关或距离阈值。
- 距离只取源码 `ensure_in`，不取可选偏好或附牌地点继续扩散。多入口主干以其任一合法入口的最短距离归堆，不把这一静态展示当作实际连续路线。没有可达主干时，独立任务仅按整堆共同的零距离起点合并，避免多入口桥接；未知/不可达或 `None` 不能强行归堆。缺失/空起点显示错误。
- 卡片只显示任务名称、沿用任务主题的彩色状态圆点、地点图标和地点文字；状态含义保留在 tooltip/无障碍标签。目录、前序数量、无前序提示不重复写在卡片上。算法/源码声明说明只留文档，不作为页面常驻文案。
- 鼠标悬停、键盘聚焦展开叠牌，角标可固定展开，长牌组内部滚动。卡片为 168×76px；缩放和适应宽度仅影响展示。三个任务视图复用顶部唯一的全字段模糊搜索；选中结果后固定展开所属牌堆，滚动并聚焦具体卡片，未启用结果仅解除显示过滤，不启用任务。未保存草稿确认和保存中保护同选卡行为，重新聚焦搜索取消旧失焦计时器。
- 默认显示启用任务及其前序闭包，停用前序保留灰色参考节点，不自动启用。“加入任务”启用已注册任务；“移出执行图”停用任务，不删脚本、参数或依赖，停用前序将不再阻塞后继，操作前明确提示。
- 选卡后查看地点、编辑前序与调度推荐地点，支持恢复默认；偏好只影响调度，不影响叠牌。保存成功才接收服务端投影并自动重排，失败保留草稿。图编辑与原任务/排序保存共用 FIFO，入队冻结快照；排队期间账号/角色变化拒绝图提交。运行占用时不可编辑。
- 静态距离由 `GET /api/task-planning/locations` 按需读取；不做设备识别、不更改导航当前位置、不加入 runtime 轮询。图不假定推荐地点就是结束地点，因此不承诺一整轮的实际路线。
- 图约束仍保存在角色任务的 `after_tasks`，不是旧 `hard_edges`；不加载 `TaskDagCanvas.js` / `TaskRulesPanel.js`，不保存坐标，不调用兼容 layout 接口。

界面展示前置阻塞、配置异常及最近一次实际决策（位置、候选成本、选中任务）。页面轮询不截图、不操作设备，也不承诺未知结束地点下的整轮路线。
